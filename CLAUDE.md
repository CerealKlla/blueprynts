# Blueprynts

Construction and blueprint authoring mod for a modular Minecraft project (Minecraft Java Edition). Part of a suite of intercommunicating mods that expose public APIs so other mods — the user's own and third parties' — can integrate.

## Context directory — read this first

`context/` is a **separate private repo**, not part of this one — it's listed in `.gitignore` here and must never be committed to this repo. It's cloned as a subdirectory at `context/` for local convenience. If this directory is missing (e.g. a fresh clone of just this repo), restore it with:

```
git clone https://github.com/CerealKlla/blueprynts-context.git context
```

(Both `blueprynts` and `blueprynts-context` remotes exist under CerealKlla and are pushed and up to date as of 2026-09-27.)

Before searching source for architecture, ownership boundaries, API shape, or "why does this work this way," check `context/` first. It's maintained specifically to answer those questions cheaply:

- `context/design-document.md` — the authoritative design spec for what's actually been built (the Construction Site mechanic and its planned next round). Note: the repo root also has a much larger, earlier `design-document.md` describing a general-purpose Blueprint/Construction-Project framework — that root document is background/candidate future scope, not what got built; `context/design-document.md` explains the relationship and is authoritative for anything already implemented.
- `context/decisions.md` — dated log of decisions made during implementation that extend or override the design document, with rationale. Check this for anything that looks like it contradicts context/design-document.md — the doc should already reflect the current decision, but this explains why.
- `context/classes/` — one short markdown file per implemented class (or a small tightly-related group of classes, e.g. all payload records together) — public surface, key state, collaborators. Read the relevant file here before opening the actual source, and before editing a class update its file to match.

**Keep this system current as you work:**
- When a design decision is made that conflicts with or is absent from context/design-document.md, update it directly and add a dated entry to context/decisions.md explaining the change.
- When a class is added or its public surface changes, add or update its file in `context/classes/`.
- Don't let source and these docs drift — treat updating them as part of finishing the change, not optional cleanup.
- `context/` has its own git history, independent of this repo's commits. Commit and push changes there separately (`git -C context add . && git -C context commit -m "..." && git -C context push`) — editing the files alone doesn't back them up.

## Status

Scaffolded 2026-09-27 mirroring Settlemynts' own setup exactly: NeoForge 26.1.2.109, Java 25, `com.github.cerealklla.blueprynts` / `blueprynts`. Settlemynts is an **optional** soft dependency (not required) — the only integration point today is bridging built-in Blueprint Types into Settlemynts' Zone Type registry if present.

**V1 (the Construction Site mechanic) implemented and live-playtested the same day** — see [context/decisions.md](context/decisions.md) for the full dated history, including ten real bugs found and fixed during live testing (perimeter-fit asymmetry was actually a Settlemynts-side bug, found while testing this mod alongside it — see Settlemynts' own context repo). In short: a Construction Site block lets a player design a free-form (player-drawn, not fixed-rectangle) footprint via budgeted Footprint Slabs, build within a protected volume with a walk-away auto-clear safeguard, and Save/Load the result as a reusable Blueprint. See [context/design-document.md](context/design-document.md) for the full mechanic and [context/classes/](context/classes/) for per-class reference.

**Since then, also implemented and confirmed live**: Blueprint storage moved to a global file-based store (survives a server wipe, no per-dimension scoping); `templateVersion` + groundwork for a multi-reviewer voting-based Accept process (data shape only); and a full Load picklist with real preview images (`BlueprintPickerScreen`, backed by a new standalone renderer project, **[BluepryntImager](https://github.com/CerealKlla/BluepryntImager)**), a client-side `Full`/`Minimal`/`None` Preview Quality setting, and local caching. See context/decisions.md's dated entries for the full history, including two real bugs a live test caught and fixed (a client crash from an invalid texture `Identifier` path, and a too-tight terrain-clearing margin on Load) — both now confirmed live as of 2026-09-28. V3 is fully verified.

**V2's refund pile + glass ceiling implemented and fully confirmed live, 2026-09-28** — see context/decisions.md's dated entries for the full history, including five real bugs a live playtest round caught and fixed: a refund pile that paid out the site's own leveled dirt/wool as if the player had built it (fixed by excluding the untouched "site filler" sentinel), side walls stopping one block short of the ceiling, stairs pasting 180 degrees off on Load (and the same bug independently in **BluepryntImager**'s preview renderer — both fixed the same day), Load only re-clearing a bounding box around the built content instead of the entire original plot (losing any deliberate "white space" a player designed around their structure), and invisible text on all three construction screens (a bare-RGB alpha=0 bug, the same mistake Yconomics' Coin Purse decorator hit earlier). Refunds go into a Yconomics Loot Bag when that optional dependency is loaded (`bridge.YconomicsLootBridge`), falling back to a plain scattered item otherwise. The "untouched site filler" sentinel is now a dedicated `ExistingBlock` (visually brown wool, breakable, never obtainable) rather than real `Blocks.BROWN_WOOL`, so a player's own real wool always behaves normally.

**"The Ancestors" reference blueprint set hand-authored, 2026-09-28/29** (see [context/decisions.md](context/decisions.md), and design-document.md's new "Hand-authoring Blueprint JSON files" section) — a full set of 15 Blueprints (Farm/Lumberyard/Blacksmith x Tier 0-4), built outside the in-game tool via a generator script, for reference/testing content. Several real, generally-applicable authoring constraints were found live: forward-axis bounds are asymmetric (never 0/negative), door placement must be on the low-forward-coordinate wall, and — the most significant one — `loadBlueprint` pastes cells one at a time with immediate neighbor-support checks, so a support-dependent block (ladder, torch) must appear in the cells array AFTER its supporting neighbor or it drops as a free item on paste. Confirmed live in the Dev Server world; pushed to Production 2026-09-29.

**Settlemynts now also optionally depends on Blueprynts, 2026-09-29** (see [context/design-document.md](context/design-document.md)'s "Cross-mod integration" section) — the reverse direction of this mod's own existing optional Settlemynts dependency: finalizing a Settlemynts plot auto-places a box via this mod's own new API (see next entry).

**Construction Box Blueprint selection added, later the same day** — right-clicking the box now opens `ConstructionBoxPickerScreen` (a simple paged name list, no preview images yet) and selecting a Blueprint places a new `ConstructionSiteBlock` next to the box (same position/facing the box was already given) and loads it immediately via the existing `loadBlueprint`. Known gap: the picker isn't filtered to Blueprints the plot can actually fit yet (needs the plot's own polygon, not currently available to this block) — `Cartographyr.geo.PlotValidity#hasLargeArea` was added for this but not wired up. `./gradlew build` green; **confirmed live, 2026-09-29** — loads a Blueprint successfully end-to-end, but the user flagged unspecified issues to iterate on later (not yet detailed — pick up when raised, don't guess in the meantime).

**"Reposition Supply Box" implemented; long multi-bug debugging arc, 2026-09-29** (see [context/decisions.md](context/decisions.md), [context/classes/ConstructionBox.md](context/classes/ConstructionBox.md)) — several live tests each surfaced a genuinely different real bug, two dead-end theories were pursued and explicitly retracted. **Tier renumbering (T0-T4 -> T1-T5) implemented, same day** (see [context/design-document.md](context/design-document.md), [context/decisions.md](context/decisions.md)) — the first piece of the above picked up in isolation, per the user's own request. `TierSpec` is now five constants (`T1`-`T5`, dropping the old `T0` and old top tier `T5`), and every tier-related int in the codebase is now that same 1-based number, not a separate 0-based index. The 15 "Ancestors" Blueprint JSON files (plus a separate `town_hall` test set) in the Dev Server's own store were migrated to match — Production's copy was deliberately left untouched, not asked for this pass. `./gradlew build` green; **live confirmation (Construction Site UI tier cycling, Loading a migrated Ancestors Blueprint) still pending.**

**Construction Box funding core loop + Blueprint build-order Sequence implemented, 2026-09-29, confirmed live 2026-09-30 after several real fix rounds** (see [context/design-document.md](context/design-document.md), [context/decisions.md](context/decisions.md), [context/classes/ConstructionBox.md](context/classes/ConstructionBox.md) for the full account) — a new closed `GenericResource` enum (Wood/Stone, tag-backed), a `BlueprintCell.sequence` field computed once at Save time by new `SequenceComputer` (ground floor first, then alternating below/above, plus a same-layer support-dependency topological sort so a wall-mounted block like a ladder is always sequenced after the wall it's on), a percent-aware `RealBlueprintPlacement.place` overload, and this mod's first real `Container`/`MenuProvider` (`ConstructionBoxMenu`/`client.ConstructionBoxScreen`, `registration.ModMenus`, mirroring Yconomics' Loot Bag precedent). Selecting a Blueprint binds the box and opens a Supplied/Needed funding screen; construction paces itself by `min(funded%, elapsed-time%)` — **funding and construction progress are two deliberately separate numbers**, per explicit user correction, decoupled via a new per-box `minTimeTicks`/`boundAtGameTime` (read from Settlemynts) and a once-a-second ticker. A real, unrelated stale-tier bug (`record.tier() == 0`, missed during the renumbering above) was caught and fixed in the same pass.

Several real bugs found and fixed across this live-test arc, all detailed in decisions.md: overlapping GUI text and no build-location indication (fixed with a real layout + a ghost preview outline, clearing at >5% progress); `ConstructionBoxMenu` reading state straight off its own `box` field, which is always `null` client-side, silently breaking "Relocate Building"'s active-state and "Reposition Supply Box"'s payload (fixed by routing everything through `ContainerData`); "Reposition Building" only working once a structure was fully built (fixed — it now works pre-build too, moving the pending anchor without bypassing funding); and a reposition race where the ticker resumed building at the old anchor before a new one was placed, leaving orphaned blocks and locking out further reposition (fixed with a new `repositionPending` suspend flag). A new DEBUG-only `/blueprynts resequence`/`resequence_all` command backfills real `sequence` ordering onto the pre-existing "Ancestors" Blueprints, which otherwise build front-to-back (on-disk order) instead of ground-up, since they predate the Sequence field. `./gradlew build`/`test` green throughout, whole-suite rebuild green. **Confirmed live, 2026-09-30.**

**Moving a building onto its own Construction Box (or a future Plot Config Sign) no longer destroys it, 2026-09-30** (see [context/decisions.md](context/decisions.md), [context/classes/ConstructionBox.md](context/classes/ConstructionBox.md)) — real bug report: moving the box into a building's own footprint is intentional and supported, but a later building move landing on top of it used to silently overwrite/destroy it. New `construction.ConstructionBoxOverlapGuard`, called right before every real paste, relocates any Construction Box sitting in the incoming footprint to the nearest free spot on the plot's buildable-area edge, copying its full state onto the freshly-placed block — including the case where the box relocating is the very one whose own method is running (handled via a reported new-position hand-off so the caller switches instances instead of continuing on a stale one). Structured so a future Plot Config Sign slots into the same check without restructuring it. `./gradlew build` green.

**Small read-only facade addition, 2026-09-30, for Settlemynts' new Plot Config Sign** — `api.Blueprynts#getConstructionBoxStatus(ServerLevel, BlockPos)` exposes a Construction Box's own `everCompleted`/`plotArea` state read-only, so Settlemynts can react to it without ever importing `construction.ConstructionBoxBlockEntity` directly. This mod still knows nothing about a Settlemynts Plot — confirmed explicitly with the user mid-build of that feature (see Settlemynts' own CLAUDE.md/decisions.md for the full Plot Config Sign account, including a correction to how/when it spawns).

**Two more real bugs found and fixed, same day, from the Plot Config Sign's first live test** (see [context/decisions.md](context/decisions.md)) — the overlap guard above only covered `RealBlueprintPlacement`'s paste step; `ConstructionBoxBlockEntity#clearPartialConstruction`'s own terrain-restore step (runs on every "Reposition Building" click) was a separate, unguarded path that could silently destroy a box/sign sitting inside the footprint being cleared, exactly reproduced live ("moved the building, and then placed the Construction Box inside the building... tried to move the Building again, which deleted the building and Construction Box"). Fixed the same way, and `clearPartialConstruction` now returns the (possibly relocated) active instance rather than `void`, since its caller mutates the box further afterward. Separately, `BuildingLocatorItem`/`SupplyBoxLocatorItem` both gained real walk-away/death/logout auto-cancel (`cancelIfHeld`, a new `LocatorCancelListener`) — a design-doc-described behavior that, on inspection, had never actually been built for either, confirmed by a real playtest report ("walking away from the plot never auto-canceled the move and never removed the item"). `./gradlew build`/`test` green.

**Same-day follow-up: the new auto-cancel could fire the instant a Locator was granted** (see [context/decisions.md](context/decisions.md)) — a Building Supply Box sits right at the plot's edge, so a player right-clicking it to start a reposition is very often standing just outside the plot's strict interior at that exact moment; the very first walk-away check could already see "outside" and cancel the brand new item immediately. Fixed with a new shared `LOCATOR_GRANTED_AT_GAME_TIME` component + a 3-second grace window (`LocatorGracePeriod`) before the walk-away check starts applying at all. `./gradlew build` green.

**Final round, same day: the overlap guard's real remaining gap was a Y assumption, not a missing check** (see [context/decisions.md](context/decisions.md)) — two more reports pinned it down: an instant-complete-on-reposition bug (traced to `PendingSupplyBoxRelocation` silently losing funding/time-gate state across a Supply Box relocation — fixed by restoring via the box's own comprehensive `copyStateFrom` instead of a hand-picked, inevitably-incomplete field subset), and, more decisively, "I moved the Construction Box into the building while it was still being built and it destroyed the box. This is definitely something that will happen in the future." Root cause: both overlap-guard call sites only ever checked a *single* Y (the site's own ground floor) per footprint column — a box anywhere off ground level was invisible to the check. Fixed with a new `RealBlueprintPlacement#computeFootprintPositions` (the real 3D volume, not a flattened column set) and `ConstructionBoxOverlapGuard#relocateObstructions` now taking `Set<BlockPos>` instead of `Set<Column>`. Temporary `[BOX-DEBUG]`/`[OVERLAP-DEBUG]` logging (added to chase this rather than guess blind, per this session's own established convention) has been removed now that all three reported scenarios were retested live in one pass. `./gradlew build`/`test` green. **Confirmed live, 2026-09-30** — this closes out the whole Construction Box overlap-guard arc for now.

**NPC auto-funding, 2026-09-30** (see [context/classes/ConstructionBox.md](context/classes/ConstructionBox.md), Settlemynts' own CLAUDE.md for the periodic-delivery side) — the next piece of the long-pending Section 14a design picked up, per explicit user choice. This mod's own half stayed deliberately thin: `maxTimeTicks` (accepted since 2026-09-29 but never stored) now persists on the box the same way `minTimeTicks` already does, including through `copyStateFrom`; a new `isFundable()` replaces `attemptCompletion`'s duplicated guard; and `api.Blueprynts` gained `getNpcFundingState`/`depositResource`, both thin read-only-facade wrappers over state/methods (`requiredAmount`/`suppliedAmount`/`deposit`) that already existed. The actual periodic delivery loop — which plots qualify (NPC-owned, i.e. no Owner set), how much to deliver, how often — lives entirely in Settlemynts' new `construction.NpcAutoFundingTicker`; this mod still knows nothing about plot ownership. `./gradlew build` green in both repos, whole-suite rebuild green. Same day, the user asked for the rate model to be restructured into two named, independently-config-derived quantities instead of one combined formula — pure Settlemynts-side change, this mod's own facade methods didn't need to change (see Settlemynts' own CLAUDE.md). **Confirmed live, 2026-09-30** — "was confirmed working a long time ago" (see Settlemynts' own CLAUDE.md).

**Fixed, same day: the Building Locator/Construction Box picker preview also spawned in tree canopies** (see [context/decisions.md](context/decisions.md)) — `construction.GhostBuildingPreviewEntity` had the same `Heightmap.Types.WORLD_SURFACE` bug a Settlemynts-side live report traced first (a Construction Box/Plot Config Sign spawning floating in a tree — see that mod's own CLAUDE.md for the full root-cause writeup); switched to `MOTION_BLOCKING_NO_LEAVES`, same fix. `./gradlew build` green. **Confirmed live, 2026-09-30** — "works correctly now" (see Settlemynts' own CLAUDE.md).

**Fixed, same day: repositioning the Supply Box also silently moved the pending/mid-build structure** (see [context/decisions.md](context/decisions.md), [context/classes/ConstructionBox.md](context/classes/ConstructionBox.md)) — `anchorPos()`/`anchorFacing()`'s "fall back to the box's own position" default kept tracking the box's *new* position once "Reposition Supply Box" moved it, dragging the building's target along even though the two repositions are meant to be independent. Fixed by pinning the current anchor explicitly (`box.setPendingAnchor(box.anchorPos(), box.anchorFacing())`) before the box itself relocates. `./gradlew build` green. **Confirmed live, 2026-09-30.**

**Removed the pending-build ghost-glass preview entirely, same day** (see [context/decisions.md](context/decisions.md), [context/classes/ConstructionBox.md](context/classes/ConstructionBox.md)) — explicit user request, no replacement. `ConstructionBoxBlockEntity#spawnPendingPreview` and its two call sites/discard points deleted outright; `GhostConstructionWallEntity` itself untouched since the Construction Site footprint-authoring tool still uses it for its own preview. `./gradlew build` green. **Confirmed live, 2026-09-30.**

**Fixed, same day: walking away mid-Reposition Building permanently lost the structure** (see [context/decisions.md](context/decisions.md), [context/classes/ConstructionBox.md](context/classes/ConstructionBox.md)) — real report: "if you start relocating a building but then walk out of the plot it doesn't restore the building to it's previous location." `BuildingLocatorItem#cancelIfHeld`'s walk-away auto-cancel used to just discard the stray item, on the mistaken assumption nothing needed restoring; in fact `clearPartialConstruction` already tears the structure down the instant "Reposition Building" is clicked. Fixed since `pendingAnchor`/`pendingFacing` are never touched by that click itself -- `cancelIfHeld` now clears `repositionPending` and calls `attemptCompletion` again, which re-pastes at the still-current anchor up to the same funded/time-based percentage as before. `./gradlew build` green. **Confirmed live, 2026-09-30.**

**Fixed, same day: shift-clicking resources into a Construction Box silently did nothing** (see [context/decisions.md](context/decisions.md)) — real report: "I tried to manually add wood logs into a construction box and it wouldn't accept it, despite there being only 10/50 'wood'." `ConstructionBoxMenu#quickMoveStack` unconditionally no-opped on every shift-click with zero feedback, so a player's instinctive "manually add" move (shift-click, not drag-to-slot) silently failed. Now routes a shift-clicked player-inventory stack through the same `GenericResource` matching/`onDeposit` path the direct-drag funding slot already uses. A real, needed fix, but **not the actual blocker** — see the next entry.

**Fixed, same day: the real blocker — Construction Box deposits were broken for every resource, not just wood, because the custom item tags lived in the wrong folder** (see [context/decisions.md](context/decisions.md)) — live retest of the fix above found drag-and-drop also failing for every species/resource tried. Root cause, found only after temporary debug logging ruled out the two more plausible-looking theories first (shift-click-only; then `BuiltInRegistries.ITEM.wrapAsHolder` returning an unbound holder): Minecraft 26.1.2 flattened vanilla's own data-pack tag folders from plural to singular (`data/minecraft/tags/item/`, confirmed by inspecting the real client jar), and this mod's custom tags were still sitting at the old plural `tags/items/` — silently never loaded as a real tag at all, no error, just permanently empty. Renamed to `tags/item/`; `GenericResource#matches` kept its `new ItemStack(item).is(tag)` form from the ruled-out theory (still more correct than the original) plus a comment at the tag-builder call site flagging the singular-folder convention. `./gradlew build` green, confirmed the built jar actually contains the renamed path. **Confirmed live, 2026-09-30** for Wood; Stone needed one more fix, see next entry.

**Fixed, same day: Stone still wouldn't deposit after the folder fix — `generic_stone` referenced a vanilla item that was never real** (see [context/decisions.md](context/decisions.md)) — this time a real, visible `TagLoader` error named the exact cause: `minecraft:cobblestone_bricks` isn't a real item (vanilla's only stone-brick block is `minecraft:stone_bricks`, already listed separately), and one bad reference fails that entire tag's load, not just the one entry — so `generic_stone` resolved completely empty even after the folder-path bug was fixed. Removed the bogus entry. `./gradlew build` green. **Confirmed live, 2026-09-30** — "that fixed it."
